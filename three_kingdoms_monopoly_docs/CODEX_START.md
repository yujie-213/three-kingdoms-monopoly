# 给 Codex 的第一条指令（建议直接复制）

我准备独立开发一个长期培训项目《三国大富翁》，本仓库中有 `PROJECT_SPEC.md`，它是当前权威需求文档。请先完整阅读该文档。**这次先执行 M0（工程初始化与发布链路验证），不要一次性实现 M1–M5，更不要直接开始设计所有事件或精致美术。**

工作目标：
1. 检查当前目录/Git 状态，若目录非空不要覆盖用户文件。
2. 简短说明拟采用的前端目录组织、游戏引擎与 DOM 解耦方式、状态机与测试方案、Vite 构建单文件 HTML 的技术选型及风险。
3. 初始化原生 JavaScript + Vite 开发工程与自动测试配置；按规范创建 `src/core`、`src/data`、`src/config`、`src/ai`、`src/ui`、`assets`、`tests`、`docs` 等目录（空目录按需要保留）。
4. 只实现一个能运行的占位页面和最小打包验证；本阶段不用写完整骰子/土地业务逻辑。
5. 将 JS/CSS/图片（如果有）统一内联进**一个** HTML 发布产物，验证其在离线 `file://` 下可打开，说明打包命令和发布文件确切路径。不要声称验证了未实际测试的项目行为。
6. 初始化 `README.md`、`docs/GAME_RULES.md`、`docs/DECISIONS.md`、`docs/TODO.md`、`docs/HANDOFF.md`、`CHANGELOG.md`；将项目规范中确认规则与待确认的默认值分开记录。
7. 检查是否已有 Git 仓库，尊重现有历史；不要删除已有文件；说明 .gitignore 原则，禁止把密钥和不必要生成物提交。
8. 运行能够执行的测试/构建，并报告确切结果和局限。

验收要求：开发页面启动成功；能生成单 HTML 文件；确认未通过外部资源加载内容；工程结构清晰；README 写明运行/构建/离线试玩操作；交接文档说明下一阶段 M1 的第一个小任务。

操作方法：**先给出不超过一页的实施方案；如果权限允许并且没有覆盖、删除或其他不可逆风险，再开展 M0 实施**。若遇到影响架构的需求不确定点，先说明拟采用的可配置默认值和原因，不要自行篡改已经确认的产品规则。

完成 M0 后请停止，不要提前继续做 M1。
